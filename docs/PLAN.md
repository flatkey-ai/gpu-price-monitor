# 竞品算力价格监控实施方案

方案日期：2026-10-15。当前为项目初始化，所有采集和发布功能均待实现。

## 目标和范围

首期监控 Nebius、Lambda、Crusoe、AutoDL、UCloud 的 GPU 云实例或容器租赁报价，每日形成可追溯快照，支持竞品比较和后续定价决策。模型 Token、托管推理、硬件销售及裸金属整机不纳入首期比较集。

按需、抢占式、包月和包年形成不同价格序列。默认比较明确配置的按需报价；“低至”、询价和条件不明的报价不进入确定价格排名。

## 监控目标

目标由平台、产品线、销售站点、销售国家、服务国家、地区、可用区、原始 SKU、GPU 版本及显存、卡数、CPU、内存、磁盘、计费方式、币种、税费及报价身份组成。

先发现平台实际可售规格和地区，再根据监控清单启用目标。不生成不存在的地区和规格组合。配置变更后保留旧目标和旧历史；地区变化不能表现为同一目标涨跌价。

网页选择筛选器后必须确认实际选中状态。API 显式传入地区与配置，保存请求值和返回值。未细分地区的官网价保留原范围；库存地区与价格范围分别记录。

## 采集和处理

流程：配置 → 规格发现 → API / 网页采集 → 单位与条件校验 → 历史存储 → 变化检测 → 报告与导出。

- Lambda：官方实例目录 API，官网抽样校对，容量地区独立保存。
- Nebius：公开计价文档为主；指定配置或账号估价由认证 API 补充。
- Crusoe：仅解析 GPU instances 区块，结合来源记录购买条件的不确定性。
- UCloud：规格发现后，按固定完整配置询价，业务成功码也必须检查。
- AutoDL：授权市场页面为主，已有资源 API 只用于其实际覆盖范围。

API 优先，其次官方公开 HTML 或结构化数据，最后使用 Playwright 完成交互。解析规则应确定；无法确认单位、配置或页面结构时记为待核查，而非猜测价格。

## 价格和变化规则

保留原币金额、原始单位、计费周期、是否整机、资源组件和优惠条件。实例价按卡数折算时标注为套餐分摊价。GPU 分项不冒充整机成本；月年价格只在周期明确时生成带假设的等效小时价。

同一目标仅按原币计算厂商调价；换汇另列汇率来源和时间。对比窗口以最近有效报价为基线，明确时间间隔。新增目标不生成涨跌百分比。报价为零、缺货、询价、采集失败、数据过期分别处理。

默认变化提醒阈值建议为 5%，允许配置。新卡型、新地区、认证失效、页面结构变化和数据过期也生成事件；异常数量级变化先核查。

## 技术和部署

Python 3.11+；API 采集、浏览器交互、存储和发布采用独立模块。SQLite 作为首期单节点历史库，Docker 运行采集程序，生成静态看板和 CSV / JSON。

推荐固定 CPU 主机运行需要登录状态的采集任务，持久化数据库、会话和私有证据。公开来源可使用 GitHub Actions；后续提供对应运行示例。当前 CI 仅检查代码和配置，没有定时采集或数据发布。

每日计划为北京时间 09:17 主采集、11:47 对缺失目标补采，超过 30 小时未成功更新标记过期。补采发生时记录真实采集时间，不伪造主采样时刻。每日快照不代表全天最低 Spot 价格。

独立于采集任务检查最近成功时间，防止调度器停跑后无法自报。限制并发、遵守厂商速率限制，按错误类型重试。完整发现多次确认后才能判定规格下架。

## 看板

提供当前报价、同条件历史趋势、目标覆盖及采集状态。筛选国家、地区、GPU、显存、卡数、计费方式、币种、价格身份和可用状态；详情展示资源包、时间、条件及来源。

公开导出只包含适合发布的公开字段。自家报价、合同价和账号策略可在私有部署中用于比较，不自动发布。

## 实施和验收

预计 2–3 周开发，加 7 天试运行，取决于凭据、平台访问及登录页面稳定性。先完成模型和首批公开数据，再接账号 API / 浏览器，最后部署和展示。

验收覆盖单位换算、国家和地区切换、多卡配置、税费币种、生效日期、失效认证、页面变化、重复采集、失败补采及数据过期。每家抽样与官方来源对照；失败不会覆盖有效报价或触发虚假降价。

需要组织仓库权限，以及后续的 Lambda API key、UCloud 询价凭据和 AutoDL 授权会话。只有启用 Nebius 估价分支时才需要其认证。凭据通过部署环境配置，不能写入仓库或 Issue。

运行不需要 GPU；主要成本为 CPU 主机、存储备份和维护。部署选型后再核算实际月费。
